# Human Approval Execution Flow

## Approval Workflows
When the AI recommends an operational change (e.g., "Write off 5 hours of WIP due to rework"), it generates an Action Card in the UI. The user reviews the deterministic impact (e.g., Margin drops from 20% to 18%) and clicks "Approve". 

## Override Semantics
The user can modify the AI's payload before execution. If the AI suggested writing off 5 hours, the user can change it to 2 hours, preserving human authority.

## Approval Attribution
When the human clicks "Approve", the underlying database transaction is executed using the human's `userId`. The `domain_event` logs that the action was `executed_by: UserA`, with an optional metadata tag `assisted_by: AI`. This guarantees strict operational accountability.

## Escalation Handling
Certain actions drafted by the AI (e.g., issuing a Credit Note) require Director-level approval. The UI detects the user's role; if insufficient, the Action Card changes from "Approve" to "Request Director Approval."

## Operational Review Lifecycle
Action Cards generated by the AI are ephemeral. If the user navigates away or ignores the suggestion, it is discarded. The AI does not maintain a persistent queue of "Pending AI Tasks."

## Rollback Visibility
If an AI-assisted action is approved but later deemed incorrect, the standard Plinth adjustment mechanisms (Phase 4) are used to append a reversing entry. The AI cannot "undo" its own actions autonomously.
