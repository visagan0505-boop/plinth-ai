# Intelligence UI Strategy

## Intelligence Presentation Philosophy
Plinth's Intelligence UI is designed around **Operational Trust**. Rather than obscuring complex metrics behind sleek, generic graphics, the UI explicitly surfaces the raw math and trajectory lines that drive analytical conclusions.

## Operational-First Visualization
The presentation must answer "Why does this matter right now?" Visualization avoids vanity metrics and focuses purely on operational intervention points (e.g., jobs nearing fee exhaustion, staff nearing burnout).

## Deterministic UI Constraints
All charts and metrics rendered in the intelligence views must strictly tie back to the read models generated by the deterministic aggregators. No client-side extrapolation or "smoothing" of data is permitted if it misrepresents the underlying transactional truth.

## Confidence Visibility Rules
Every intelligence widget (especially forecasts) must visually encode its confidence score. A low-confidence forecast must be visually distinct (e.g., greyed out, dashed lines, explicit warning icons) to prevent users from making hard operational decisions on soft data.

## Analytical Drilldown Rules
If an intelligence widget claims a metric (e.g., "Burn rate accelerated 40%"), the user MUST be able to click that metric and view the exact time entries, invoices, or domain events that contributed to that claim. Intelligence without drilldown is a black box.
