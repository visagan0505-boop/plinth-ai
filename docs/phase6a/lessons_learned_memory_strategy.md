# Lessons Learned Memory Strategy

## Lessons-Learned Indexing
Consultancies bleed margin when they repeat the same mistakes across different jobs. Plinth's operational memory explicitly indexes "Lessons Learned" at the conclusion of a job. This is an explicit operational entity combining qualitative human retrospectives with quantitative intelligence (WIP overburn, margin degradation).

## Operational Risk Recall
Before a new job transitions from `FEE_PROPOSAL` to `ACTIVE_DELIVERY`, the AI memory layer queries the semantic index for similar historical jobs (matched by client, discipline, fee size, and text embeddings). It surfaces relevant lessons learned and previous risk flags to the Project Manager to preemptively mitigate structural risks.

## Human Validation
Lessons Learned are not autonomously generated by AI. The AI may *suggest* a lesson (e.g., "This job overburned by 40% due to geotechnical revisions. Shall I log a lesson learned?"), but the Project Manager must approve and curate the text before it enters the authoritative memory index.
