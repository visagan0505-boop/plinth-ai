# Workload Visibility Strategy

This document defines how the platform exposes engineering workload.

## 1. The Workload Definition
Workload in Plinth is defined by **active operational surface area**, not by assigned "tasks".
If a staff member is actively logging telemetry against a Phase, or is creating Revisions for a Deliverable, they are carrying workload for that Job.

## 2. Activity Heatmaps
Workload visibility will be rendered via activity heatmaps or recent-action ledgers. This shows *where* the engineering effort is currently flowing within the firm.

## 3. No Task Assignment
We explicitly reject the Jira model. We will not build "Task Assignment" views showing a backlog of tickets. We show *actual effort expended* via telemetry and *actual documents produced* via revisions, surfacing the true operational reality rather than a speculative plan.
